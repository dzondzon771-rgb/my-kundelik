SMART STAROSTA v7 — БӨЛІМ МЕҢГЕРУШІСІНІҢ ЕСЕПТЕР ПАНЕЛІ
====================================================

ЖАҢА МҮМКІНДІК
- Староста бұрынғыша өз күнделігін өңдейді.
- Бөлім меңгерушісі дәл сол кіру терезесіне өзінің email/паролін енгізеді.
- Firebase staffRoles/{UID} ішінде role = department_head болса ғана
  «Старосталардың есептері» панелі ашылады.
- Меңгеруші тек өзінің departmentId бөліміндегі мүшелерді көреді.
- Ол топ, күн және студент бойынша қатысу статистикасын қарайды,
  бірақ журналға өзгеріс енгізе алмайды.
- Меңгерушіге private diary-дің толық мазмұны берілмейді; ол тек
  reports/{UID} құжаты арқылы топ, староста, студенттер және қатысу
  белгілерін көреді. Жеке жазбалар (notes) жарияланбайды.

МАҢЫЗДЫ: Firebase жобасына тікелей қатынай алмаймын, сондықтан нақты
меңгеруші аккаунтын өзіңіз Firebase Console арқылы тіркеуіңіз керек.
Жоба тек дайын рөл логикасын, қауіпсіздік ережелерін және панельді қамтиды.

1) АЛДЫМЕН FIRESTORE RULES ЖАРИЯЛАҢЫЗ

   https://console.firebase.google.com/ → mykundelik
   Firestore Database → Rules
   Архивтегі firestore.rules файлының БАРЛЫҚ мәтінін көшіріңіз.
   Publish басыңыз.

   Ескерту: бұл жаңа ережелер «reports» және «staffRoles» жинақтарын
   қолданады. Ескі ережелермен v7 қосымшасына кіру/жазу жұмыс істемеуі мүмкін.

2) МЕҢГЕРУШІ АККАУНТЫН ЖАСАҢЫЗ

   Firebase → Authentication → Users → Add user.
   Меңгерушіге жеке email және КҮШТІ құпиясөз орнатыңыз.
   Құпиясөзді жарияламаңыз. Сол аккаунттың UID мәнін көшіріңіз.

3) МЕҢГЕРУШІГЕ ҚҰҚЫҚ БЕРІҢІЗ (тек Firebase жобасының иесі орындайды)

   Firestore Database → Data → Start collection → staffRoles.
   Document ID: меңгерушінің Authentication UID мәні (email ЕМЕС).
   Fields:
      role           (string) = department_head
      departmentId   (string) = <бөлімнің өз коды>
      departmentName (string) = <бөлімнің өз атауы>

   Мысал үшін бөлім коды «dept-01» бола алады, бірақ бұл
   қосымшаның алдын ала толтырылған мәні ЕМЕС.
   Меңгеруші рөлін HTML ішіндегі бір батырма арқылы қоюға БОЛМАЙДЫ.

4) СТАРОСТАНЫ БӨЛІМГЕ ҚОСЫҢЫЗ

   Староста өз аккаунтына кіріп, жоғарғы «ID көшіру» батырмасын басады.
   Firestore → Data → departments → [бөлімнің коды]
   Егер құжат жоқ болса, құжат жасаңыз (name деген string өрісті
   өз қалауыңызбен енгізуге болады).
   Осы бөлім құжатының ішінде subcollection: members
   Member document ID: старостаның UID мәні.
   Қажет болса label (string) өрісін өзіңіз енгізіңіз.
   Әр старостаға бір жеке members құжаты қажет.

   Мысалы:
   departments
     /dept-01
        /members
           /STAROSTA_UID_1
           /STAROSTA_UID_2

   ЖЕКЕ МӘЛІМЕТТЕР: тек өкілетті меңгерушіге ғана рұқсат беріңіз.
   Бөтен адамның UID-ін бөлімге рұқсатсыз қоспаңыз.

5) GITHUB PAGES-ТА ЖАҢАРТУ

   GitHub → dzondzon771-rgb/my-kundelik → Add file → Upload files.
   github-pages архивінен сайттың түбіріне мына файлдарды жүктеңіз:
     index.html
     cloud-v7.js
     cloud.js
     head-dashboard.js
     head-dashboard.css
     sw.js
     manifest.json
     icon-192.png
     icon-512.png

   Commit changes → Actions → pages build and deployment Successful.
   Сайтты .../my-kundelik/?v=7 деп ашып тексеріңіз.
   Егер телефонда ескі нұсқа тұрса, PWA кэшін жаңарту қажет болуы мүмкін.

6) ANDROID / IPHONE

   Мобильді ZIP ішіндегі www/ файлдары осы v7 нұсқасын қамтиды.
   Бұрынғы Capacitor жобасымен қайта жинаңыз:

      npm install
      npx cap add android         (егер android/ бұрын жасалмаған болса)
      npx cap sync android
      npx cap open android

   iOS үшін Mac+Xcode:

      npm install
      npx cap add ios             (егер ios/ бұрын жасалмаған болса)
      npx cap sync ios
      npx cap open ios

   ЕСКЕРТУ: ZIP — бастапқы код. Дайын қолтаңбаланған APK/IPA емес.

7) ҚАЛАЙ ТЕКСЕРУ КЕРЕК

   - Староста аккаунтымен кіріңіз: өзінің күнделігі ашылуы керек.
   - Меңгеруші аккаунтымен кіріңіз: «Старосталардың есептері» ашылуы керек.
   - Бөлімге тіркелген староста топтары көрсетілуі керек.
   - Меңгерушіде журналды өңдеу батырмалары болмауы керек.
   - Өзге бөлімнің мүшесі қосылмауы керек.
   - Жаңа студент белгісі жаңартылған есепте көрінуі керек.

ЕСЕПТЕУ
«Қатысу пайызы» = («Қатысты» + «Кешікті») / барлық белгіленген жазба.
«Белгіленбеді» пайызына кірмейді. «Себепті» қатыспаған ретінде
есептеледі, жеке бағанында көрсетіледі.

ҚАУІПСІЗДІК
- Firebase Security Rules жарияланбайынша рөлдік қорғаныс жұмыс істемейді.
- Firebase Console жобасының иесі ғана рөл және бөлім мүшелігін орнатады.
- Пайдаланушылардың құпиясөздерін JavaScript ішіне ЖАЗБАҢЫЗ.
- Firebase SDK веб конфигурациясы public, бірақ ақпаратқа рұқсатты
  Firestore Rules шектейді.
- Студенттердің жеке деректерін өңдеу үшін тиісті рұқсаттарды қамтамасыз етіңіз.
